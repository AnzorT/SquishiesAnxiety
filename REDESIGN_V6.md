## What the drawing code is (decides how we port it)

- **Creatures (`rive-rig.js`, `rive-generic.js` 750 KB, `plush-rig25.js`, `pet-defs.js`, `mittens-moves.js`, `rig-shuffle.js`, `creatures-v2.js`, `squad-store.js`):** live **SVG DOM**. It parses each creature's SVG art (`export/tripo/<key>/<key>-front|back|left|right.svg`, 87 creatures) into elements and rewrites their attributes every frame. It uses `<use>` and SVG filters, and `rive-rig.js` uses a canvas for a fabric texture. React Native has no DOM, and react-native-svg can't keep up with per-frame attribute edits on that many nodes.
- **Game (`ASMR Creature Squash v5`):** three.js. Spheres textured with the creature's front/back SVG art (`TextureLoader`), plus the 2D `squish-rig.js`.
- **Chests (`chest-models.js` + `chest-<group>.js` × 11, `chest-kit.js`, `chest-loot.js`, `chest-sfx.js`):** canvas 2D with real damage (dents, cracks, chunks, tear-off parts, shard break). Static card art can be rendered to PNGs offline, as `tools/shop-art/render.mjs` does today.
- **Currency (`squish-currency.js`):** canvas-built PNGs: coins stamped with a creature, gems cut in a creature's shape. Render them once offline to PNGs.

**Plan:** run the design's own rig code inside `react-native-webview` (Android System WebView = Chrome, so SVG DOM, filters and canvas all work 1:1, and design updates drop straight in).
- Use **one WebView per screen** for the live creature.
- Use offline-rendered PNG/WebP thumbnails for grids, cards and reveal stills. Render them in headless Chrome, all 87 creatures × the views we need.
- Touches (poke, drag-to-spin) are handled inside the WebView. Events go to RN through `postMessage`.
- Step 0 has to prove this is fast enough on the Galaxy A15 **release** build before anything else is built on it.

- **Works:** poke, drag-to-spin (shows the back view), shuffle moves, the move buttons, and switching creature without reloading the WebView. Mount takes 20–100 ms (Mittens ~280 ms on a cold start). Rig JS takes 2–8 ms per frame.
- **Speed:** as delivered, the median creature ran at 74 fps and 8 of 87 were under 60 (Choco 43). The cost is GPU raster of the art's own live-noise fabric-grain filter (`<filter id="ft">` with `feTurbulence`), applied to 2–4 parts separately. Result: **median 89.5 fps, 4 under 60** (Choco 53, Mamapaws 54, Biscuit 55–58, Dunkie 60). The look is the same, except the grain now also covers the eyes, as on Mittens.
- **Heavy creatures:** at `renderScale` 0.8 (the WebView drawn at 80 % size and scaled up by Android) those reach 63–73 fps and stay sharp. **Step 2: start at 1 and drop to 0.8 when `onPerf` reports < 58 fps for 2 s while idle.**
- **Memory:** the WebView process is ~200 MB PSS, but it already existed for the ad SDK. Emptying the rig page frees only ~7 MB. The app process is ~340 MB.
- **Thumbnails:** [tools/rig/thumbs.mjs](tools/rig/thumbs.mjs) renders all 87 creatures (idle pose, transparent, 512 px WebP, plus a contact sheet) in 30 s into `tools/rig/out/` (git-ignored). Avo, cakey and acorn touch the top edge: add a margin before step 1 uploads them.
